# Agent Note: Enhance CI Build Summary and Eliminate Redundant Digest Output

Status: implemented

## Problem
The GitHub Actions CI pipeline and summary reporting suffered from three issues:
1. **Redundant Digest Execution & Output**: The workflow step `Run ImmortalWrt build pipeline` invoked `uv run iwb digest` immediately after `uv run iwb build`. Because `iwb build` already collects output artifacts and writes `filedigest.md`, calling `iwb digest` redundantly recomputed checksums and duplicated log output. Additionally, `output.py` contained legacy code appending a partial `### Firmware Build Digest` heading into summary files.
2. **Sparse CI Step Summary**: The GitHub Actions summary generated by `write-ci-build-summary.py` only contained basic status, duration, and the raw checksum table, omitting essential source traceability (upstream Git repository link, source branch/tag, source commit hash, commit message, builder commit SHA, workflow run trigger, and disk usage).
3. **ccache Directory Resolution Mismatch**: When `prepare_config()` evaluated `extract_arch_signature()` before running `make defconfig`, it calculated a degraded architecture directory (`.../mediatek-filogic-generic-musl-default`) and wrote it to `CONFIG_CCACHE_DIR`. Subsequent CI steps and `export_ccache_stats` evaluated the expanded `.config` and computed `.../mediatek-filogic-aarch64-musl-14.3.0`, causing CI to save and query an empty directory while OpenWrt compiled into the generic directory.

## Decision
1. **Deduplication of CI Digest Execution**:
   - Removed `uv run iwb digest` from the `.github/workflows/build.yml` build pipeline step.
   - Refactored `write_digest_summary()` in `immortalwrt_builder/builder/core/build/output.py` and `handle_digest()` in `digest.py` to focus strictly on generating `filedigest.md` and printing the checksum table to standard output, without writing fragmented markdown sections to summary files.
2. **Authoritative & Rich CI Step Summary**:
   - Upgraded `immortalwrt_builder/scripts/write-ci-build-summary.py` to render a structured, clean GitHub Actions Step Summary (`$GITHUB_STEP_SUMMARY`):
     - **Build Overview**: Target name, status icon (`✅ SUCCESS`, `❌ FAILURE`, `⚠️ SKIPPED`), human-formatted duration, workflow run URL with trigger details (`workflow_dispatch` by user), and release URL.
     - **Source Traceability**: Upstream Git repository Markdown link, branch or release tag link, upstream commit SHA link with commit subject and date, and builder repository commit link.
     - **Firmware Artifacts**: Checksum table (MD5, SHA256, file size) loaded from `filedigest.md`.
     - **Caching & Storage**: Toolchain cache key, ccache statistics, and workspace disk usage metrics.
3. **Two-Phase `prepare_config` for Consistent Architecture Signatures**:
   - Updated `prepare_config()` in `engine.py` to execute an initial `make defconfig` to expand OpenWrt architecture symbols before resolving the ccache directory.
   - Injected `CONFIG_CCACHE_DIR` pointing to the canonical `arch_signature` directory, guaranteeing that `.config`, `iwb tools ccache-dir`, GitHub Actions cache keys, and `export_ccache_stats` share the identical partition.

## Alternatives considered
- **Injecting Digest Summary Directly in Core Pipeline**: Considered letting `iwb build` append markdown directly to `$GITHUB_STEP_SUMMARY`. Rejected to preserve the boundary where core builder modules remain environment-agnostic while `write-ci-build-summary.py` acts as the single authoritative summary composer for CI.
- **Including Defconfig and Patch Lists in Summary**: Evaluated adding full defconfig names, architecture directories, and applied patch script lists. Rejected per user specification to keep the CI summary concise and focused on source commit traceability, release links, and firmware artifacts.

## Consequences
- **Clean CI Output**: Eliminated redundant log output and duplicate checksum calculations in GitHub Actions.
- **Improved Traceability**: Builds in GitHub Actions immediately show exact upstream commits, releases, and artifact checksums in the Step Summary tab.
- **Single Authoritative Summary Writer**: All markdown summary composition is centralized in `write-ci-build-summary.py`.
